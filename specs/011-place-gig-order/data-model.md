# Data Model: Place Gig Order

## Overview

This feature creates `Pedido` records that link a `Cliente` to a specific `Gig` and one of its `Paquete`s, along with the customer's requirements for fulfillment.

## Entities

### Order (`Pedido`)

Represents a customer's request for a specific package of a Gig.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | auto | Unique identifier generated by the repository counter. |
| cliente | string | yes | Reference to the user who placed the order. |
| gig | string | yes | Reference to the Gig being ordered. |
| paqueteId | string | yes | Reference to the selected package at the time the order was placed. |
| requerimientos | string | yes | Customer-provided requirements text (min 20, max 2000 characters). |
| total | number | yes | Price copied from the selected package at creation time. |
| estado | string | yes | Order status. Defaults to `Pendiente`. |
| fechaCreacion | ISO string | auto | Timestamp when the order was created. |
| fechaConfirmacion | ISO string \| null | auto | Set when the order status becomes `Confirmado`. |
| puntuacion | number | auto | Defaults to `0.0`; set when the order is reviewed. |
| mensajes | array | auto | Chat messages associated with the order; defaults to empty. |
| canceladoAt | ISO string \| null | auto | Set when the order is cancelled. |
| canceladoPor | string \| null | auto | User reference who cancelled the order. |
| canceladoPorRol | string \| null | auto | Role of the user who cancelled the order. |
| reembolso | object \| null | auto | Refund record if a cancellation triggered a refund. |

### Gig (`Gig`)

Represents a freelancer service listing.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | auto | Unique identifier. |
| nombre | string | yes | Gig title. |
| descripcion | string | yes | Gig description. |
| categoria | string | yes | Category reference. |
| vendedor | string | yes | Freelancer reference who owns the Gig. |
| paquetes | array of `Paquete` | yes | At least one package must exist. |
| multimedia | array | no | Images/media associated with the Gig. |
| fechaCreacion | ISO string | auto | Gig creation timestamp. |

### Package (`Paquete`)

Represents a priced tier of a Gig.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | auto | Unique identifier. |
| nombre | string | yes | Package name (e.g., Básico, Premium). |
| precio | number | yes | Non-negative price. |
| diasEntrega | number | yes | Non-negative delivery promise in days. |
| descripcion | string | yes | Package description / included items. |

### User / Customer

The existing `Usuario` entity provides the `cliente` and `vendedor` references. This feature only reads user identity from the authentication context.

## Relationships

```
Usuario (cliente) 1 ---- * Pedido
Usuario (vendedor) 1 ---- * Gig
Gig 1 ---- * Paquete
Pedido * ---- 1 Gig
Pedido * ---- 1 Paquete (captured at placement time)
```

## Validation Rules

1. **Package selection**: `paqueteId` must reference a package that belongs to the Gig at the time of placement.
2. **Gig active**: The Gig must exist and have at least one active package.
3. **Requirements length**: `requerimientos` must be between 20 and 2000 characters after trimming.
4. **Price snapshot**: `total` is set to the selected package's `precio`. It must be non-negative.
5. **Status**: Initial status is `Pendiente`.
6. **Authentication**: The customer must be authenticated to place an order.

## State Transitions

The placement feature only concerns the creation transition:

```
(no order) -- place order --> Pedido(estado = "Pendiente")
```

Further transitions (Confirmado, En revisión, Entregado, Cancelado) are managed by other features.

## Idempotency

The placement endpoint accepts an optional `Idempotency-Key` header. The backend stores a mapping of recent keys to created order IDs for 5 minutes to prevent duplicate orders from rapid or retried submissions.
